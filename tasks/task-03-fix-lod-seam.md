修复上一轮改造引入的一个 LOD 接缝缺陷。只修改 `src/terrain.js`，不新增文件，不改动 `src/main.js`。

## 问题（已实测确认）

对同一坐标分别用不同 `lodLevel` 采样 `sampleHeight`，相邻档位的高度差实测如下：

```
lod0 -> lod1   avg=0.0m      max=0.0m
lod1 -> lod2   avg=30.7m     max=580.5m
lod2 -> lod3   avg=0.0m      max=0.0m
lod3 -> lod4   avg=594.1m    max=9874.7m   <-- 缺陷
lod4 -> lod5   avg=0.0m      max=0.0m
该区域总高差 29589m
```

`lod3 -> lod4` 的最大高度差达到 `9874m`，占总高差的 33%。这会在中景与远景的 LOD 环边界处产生巨大的地形台阶和裂缝。

## 根本原因

`erosion` 层内部混合了两类特征尺度完全不同的地貌：

- **超级峡谷**：由 `canyonDepthM: 9300` 驱动，是横跨数十公里的**低频大尺度**地貌。
- **沟壑细节**：由 `wavelengthM: 5200` 与 `amplitudeM: 820` 驱动，是**高频小尺度**细节。

当前 `lodLevel >= 4` 把整个 `erosion` 层一次性跳过，导致远景 LOD 完全丢失 9.3 km 深的超级峡谷。峡谷属于大地貌骨架，远景必须保留。

## 修复要求

把 `erosion` 层拆成两个独立可分级的部分：

1. **canyon（低频峡谷）**：在**所有** `lodLevel` 都必须参与计算，不允许跳过。它属于宏观地貌骨架，和 `continental`、`plateau`、`ridge` 同级。
2. **gully（高频沟壑与坡度加权细节）**：保持现有的分级策略，`lodLevel >= 4` 可以跳过，`lodLevel 2-3` 可以简化。

修复后必须满足：

- `lod3 -> lod4` 的平均高度差降到 `60m` 以下，最大高度差降到 `1200m` 以下（即小于总高差的 5%）。
- 其他相邻档位的高度差不得比现在更差。
- `lodLevel = 5` 相对 `lodLevel = 0` 的性能加速仍需保持在 `3x` 以上（当前实测 `5.53x`，允许下降但不得低于 3x）。
- 所有 `lodLevel` 的确定性不变：同一 `(x, z, lodLevel)` 重复调用结果完全相同。
- 不得放大 `LAYERS` 中任何 `amplitudeM`，也不得削减峡谷的实际深度来降低接缝差。峡谷该有多深就有多深，只是要让远景也算出它。

## 自检（不修改源文件）

1. `node --check src/terrain.js`。
2. 复现上面那张相邻档位高度差表格，覆盖 `lod0->lod1` 到 `lod4->lod5`，报告修复前后的对比。
3. 复测 `lodLevel=0` 与 `lodLevel=5` 各 20000 次采样的耗时与加速倍数。
4. 复测确定性。
5. 复测该区域的总高差，确认峡谷深度没有被削弱。
